# V1.1 关键代码阅读路线

建议从数据如何流动开始，而不是从每个控件的名字开始。

## 1. 数据结构：domain/Models.h

`Todo` 和 `Note` 是普通结构体，保存数据，不负责打开数据库或绘制界面。
`QDateTime` 无效时表示“没有时间”，数据库会写入 NULL。例如没有截止时间不是 1970 年，也不是今天。
任务截止时间和提醒时间分开，完成时间仅在完成时存在。
`QStringLiteral("")` 显式使用空字符串，避免把默认的 null QString 作为 SQL NULL 写入 NOT NULL 内容字段。

## 2. 存储：storage/Database.cpp

`QSqlDatabase` 表示一条数据库连接。每个 Database 对象使用不同连接名，便于临时数据库测试。
析构时先关闭连接、释放句柄，再从 Qt 的连接注册表移除。

`prepare()` 创建带问号占位符的语句，`addBindValue()` 绑定用户数据。引号、中文和 SQL 关键字都作为普通内容处理。
不要把标题拼接到 SQL 字符串里。

保存采用 `INSERT ... ON CONFLICT(id) DO UPDATE`：新 ID 插入，已有 ID 更新。创建时间保持不变。
首次建表放在事务里，要么全部建好并写入版本号，要么回滚；不会留下半个初始化模式。
`timestamp()` 统一把时间转换成 UTC 字符串，读取后在界面转换成本地时间。

## 3. 业务：services/PlannerService.cpp

这是所有窗口共同使用的数据入口。它持有 Database 的引用，不拥有数据库；入口函数中的创建顺序保证数据库比服务活得更久。

保存任务的顺序：清理和校验标题 → 分配 UUID/时间 → 更新提醒规则 → 写数据库 → 更新内存 → 发出 `todosChanged()`。
先写数据库再改变内存，失败时界面不会误以为已经保存。

`std::optional<Todo>` 表示“找到任务或没有找到”。调用前检查是否有值，避免处理不存在的 ID。
`todos()` 返回筛选和排序后的副本，UI 不直接修改缓存。无截止时间的任务明确排最后。

## 4. 界面：ui/TodoPage.cpp 和 TodoDialog.cpp

TodoPage 负责列表和操作入口，TodoDialog 负责输入；SQL 不进入控件代码。
对话框返回 `Accepted` 后取出数据，交给 service 校验并保存。
删除必须经过确认，默认选择“不删除”。

`connect(sender, signal, receiver, lambda)` 把事件和操作连接起来。
`QSignalBlocker` 在填充列表时暂时屏蔽信号，避免程序设置勾选状态又触发一次“用户完成任务”操作。
用户勾选后的保存使用 queued 调用，等 Qt 当前信号处理完再刷新列表，避免在处理 item 的过程中销毁这个 item。

## 5. 笔记：ui/NotesPage.cpp

`activeId_` 标记当前笔记，`dirty_` 表示内容修改后尚未保存，`loading_` 避免加载内容时误触发保存。
每次输入重启单次计时器，停止输入 600 毫秒后调用 `flush()`；这叫防抖。
切换笔记、新建、离开笔记页面和退出前也调用 flush，不需要等待计时器。

保存失败不会清空 dirty 或编辑器内容，无法安全切换时留在当前笔记，用户可复制内容或修复存储权限再保存。
自动保存不等于任何情况下都不会丢字：强制终止进程和断电可能中断最近一次防抖周期。

## 6. 提醒：services/ReminderService.cpp

Timer 只是定期唤醒，不能保证在休眠期间执行。因此每次都比较当前 UTC 时间和数据库保存的提醒时间，而不是只等待一个长倒计时。
`claimDueReminders(now)` 先保存触发状态，成功后返回至多一条；其他到期条目仍在数据库，下次继续处理。
通知层检查全局开关与托盘状态，并留出间隔，避免多条通知立刻覆盖。

保存与 Windows 显示通知无法放在同一个数据库事务里。本版选择最多提交一次，以降低重复提醒；没有送达回执，边界写在 README。

## 7. 小组件与设置

DesktopWidget 与主窗口共用同一个 service，所以勾选完成之后，两边都会响应同一个 `todosChanged()`。
它保留系统标题栏和边框，让 Windows 处理拖动、缩放；置顶通过 Qt 窗口标志控制。
QSettings 使用用户目录中的 INI，`saveGeometry/restoreGeometry` 保存窗口位置和尺寸；重新连接显示器后尽量把窗口恢复到可见区域。
开机启动是唯一需要访问 Windows 注册表的功能，只有用户主动操作开关才写入 HKCU，不自动启用。

## 8. 测试和构建

`planner_core` 是业务与存储静态库，`planner_ui` 是界面静态库。应用和测试共用同一份实现，测试不是另写一套逻辑。
Qt Test 在临时目录创建数据库，重新创建 Database/PlannerService 模拟重启，并断言内容仍一致。
窗口集成测试操作真实 Qt 控件，覆盖保存、删除确认和共享刷新；实际通知中心展示仍由人工验收。

练习建议：先给任务加一个优先级字段，设计数据库迁移，再写排序测试；完成这一步后再考虑搜索任务。每次保留可运行的 Git 提交。

## 9. 月历、Deadline 与主题

`plannedDate` 是“在哪天做”，`dueAt` 是“最晚何时完成”。这两个时间可以不同；只有计划日期也能成为日历任务。
`isDeadline` 表示独立的截止事项，业务层要求 dueAt 有值并清空计划日期。
`todosForDate()` 返回安排在该日或该日截止的事项，同一任务在同一天只出现一次；跨日任务会分别出现在计划日和截止日。

SQLite 使用 v1 → v2 事务迁移，在旧表上添加两列。SQL 插入改用显式列名，旧内容、创建时间和提醒状态保持原样。

`CalendarPage` 用 7 列 × 6 行显示一个月，包括月初/月末相邻月份的日期。`CalendarCell` 继承 QAbstractButton，保留点击和键盘焦点能力，用 QPainter 绘制圆角色卡、任务和 Deadline 标识。
绘制任务标题时按实际可用宽度截短；溢出数量放在日期右上角，完整标题保存在 tooltip 与可访问名称中。
点击日期打开当天 TodoPage；创建任务默认填入点击的日期。保存仍通过同一个 PlannerService，所有窗口收到变化信号后刷新。

`Theme.cpp` 集中定义五组主题的 ID、中文名称、背景、强调色与淡色。应用 QPalette 和少量样式表统一更新已有窗口；日历绘制也读取当前主题，避免每个界面各写一套颜色。
主题 ID 和窗口不透明度写入 settings.ini。窗口真实透明度使用 Qt 的 windowOpacity，不启用依赖平台的桌面模糊效果。默认 94%，允许 80–100%；100% 时完全不透明。
设置写入失败会回滚显示与业务值；未知主题 ID 回退到雾蓝。

## 10. 字体和提示的统一（V1.1.1）

Theme.cpp 用 QFont 设置系统字体回退和正文大小，QSS 为标题、辅助提示和笔记编辑区设置字号。字体回退避免要求用户安装额外字体。标题采用 Medium 字重，让层级清楚而不过分粗重。MainWindow 中显式设置导航项高度，避免主题切换导致行距异常。提示语区分输入引导、空状态和错误：引导可以温和，保存失败与不可撤销的删除仍须说明真实后果。
